## 一、项目基本信息

表格

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 基于 SpringBoot+Vue3 的虚拟数字资产交易平台 |
| 项目类型 | 软件工程毕业设计，前后端分离 Web 系统 |
| 后端项目名 | `virtual-trade`，端口 8081 |
| 前端项目名 | `vue-trade`，端口 8082 |
| JDK 版本 | Corretto 1.8.0_482（Java8） |
| 代码规模 | 后端 69 个 Java 文件；前端 33 个 Vue/JS 文件；数据库共 11 张业务数据表 |

**项目简介**：平台面向虚拟游戏账号、虚拟道具的线上交易，实现卖家发布商品、买家选购下单、资金托管交易、余额充值、消息通知、用户反馈等功能；集成支付宝沙箱支付，搭配可拖拽 AI 桌宠作为智能客服，同时提供管理员后台，完成用户、商品、订单、桌宠皮肤等统一管理。

## 二、系统架构设计

```
┌──────────────────────────────────────────────────────┐
│                   浏览器（用户/管理员）                 │
└──────────────────────┬───────────────────────────────┘
                       │ HTTP (Axios + 前端代理跨域)
┌──────────────────────▼───────────────────────────────┐
│          前端层 vue-trade :8082                       │
│  Vue3组合式API + Element Plus + Vue Router + ECharts │
│  ┌─────────┐ ┌──────────┐ ┌─────────┐ ┌───────────┐ │
│  │ 用户端页面│ │ 管理后台  │ │ AiPet桌宠│ │ Axios拦截器│ │
│  └─────────┘ └──────────┘ └─────────┘ └───────────┘ │
└──────────────────────┬───────────────────────────────┘
                       │ RESTful API (JSON数据交互)
┌──────────────────────▼───────────────────────────────┐
│          后端层 virtual-trade :8081                   │
│  Controller(12个) → Service(14组接口+实现) → Mapper(11个) │
│  横切通用能力：JWT鉴权 / 全局异常 / 定时任务 / 文件上传        │
└──────┬──────────────┬──────────────┬─────────────────┘
       │              │              │
┌──────▼─────┐ ┌──────▼─────┐ ┌──────▼──────────────┐
│  MySQL 8.0 │ │   Redis    │ │   第三方服务          │
│  11张业务表 │ │ 缓存/接口限流 │ │ 支付宝沙箱 + 通义千问AI │
└────────────┘ └────────────┘ └─────────────────────┘
```

架构说明：采用经典前后端分离架构，前端负责页面渲染、交互、权限路由控制；后端提供 REST 接口，承担业务逻辑、数据持久化、安全校验；MySQL 持久化业务数据，Redis 用于接口限流保护；对接第三方支付与大模型能力，所有第三方密钥保存在后端，保证安全。

## 四、数据库设计（11 张数据表）

### ER 关系（文字版）

```
user(用户) ──1:N── order(订单) ──N:1── product(商品)
    │                  │                 │
    │                  └── 1:N ── transaction_log(资金流水)
    │
    ├──1:N── feedback(反馈)
    ├──1:N── notification(通知)
    ├──1:N── recharge_order(充值单)
    └──1:1── user_pet(桌宠配置) ──N:1── pet_skin(皮肤)
                    game_type(游戏分类)
```

### 核心表关键字段

1. **user 用户表**`id, username, password(BCrypt加密), phone, avatar, balance(可用余额), frozen_balance(冻结余额), role(0普通用户 /1管理员)`
2. **product 商品表**`id, seller_id, game_type_id, title, description, price, game_account, game_password, status, image`

> 
> 商品状态：1 上架 →3 锁定 →4 已售；2 下架
> 安全设计：游戏账号密码，仅买家支付成功后才可见，防止信息白嫖。

3. **order 订单表**
`id, order_no(唯一订单号), buyer_id, seller_id, product_id, price, status, payment_method, trade_no(支付宝流水号), create_time`

> 
> 订单状态：1 待支付 →2 待发货 →3 待收货 →4 已完成 /5 已取消

4. **transaction_log 资金流水表（资金安全核心）**
`id, user_id, order_id, amount, type(收入/支出/冻结/解冻), balance_before(变动前余额), balance_after(变动后余额), create_time`

> 
> 每一次资金变动都会记录，保存变动前后余额，支持对账与追溯。

## 五、六大业务模块详解

### 模块 1：用户与鉴权模块

**登录流程**

1. 前端提交账号密码，调用`UserController.login()`
2. 后端使用 BCrypt 校验密码
3. 校验通过，JwtUtil 生成 Token，携带 userId、用户角色
4. 前端本地存储 Token，Axios 请求拦截器自动在请求头携带 Token
5. 后端全局拦截器校验 Token 合法性，校验失败返回 401 未授权

**安全措施**

- 密码 BCrypt 哈希存储，数据库无明文
- Redis 实现接口限流，防止恶意注册、暴力刷登录
- Vue 路由导航守卫：未登录跳转登录页，非管理员禁止访问后台页面

### 模块 2：商品管理模块

商品状态机流转：
`发布商品 → 上架(1) →【下单】→锁定(3)`
`锁定状态：【买家取消 / 订单超时】→恢复上架(1)`
`锁定(3) →【买家确认收货】→已售(4)`
`上架(1) →【卖家手动下架】→下架(2)`

> 
> 核心：商品锁定机制实现防超卖，商品锁定期间其他买家无法下单。

### 模块 3：订单与资金托管模块（⭐项目核心难点）

完整交易流程，全部资金操作加事务注解`@Transactional`

1. **买家下单**：创建订单，商品状态修改为锁定，防止超卖
2. **买家支付**
   - 余额支付：调用冻结方法，将可用余额转入冻结余额
   - 支付宝支付：跳转沙箱页面付款，支付宝异步回调通知后端
3. **卖家发货**：填写游戏账号密码，订单变更为待收货
4. **买家确认收货**：冻结资金划拨给卖家可用余额，订单完成
5. **订单取消场景**
   - 用户主动取消订单
   - 定时任务`OrderTimeoutTask`扫描，15 分钟未支付自动取消订单
   - 两种取消都会执行解冻，资金退回买家，商品恢复上架

**可靠性设计**

- 商品状态锁定机制，解决超卖问题
- 支付回调幂等判断：重复回调时先校验订单状态，避免重复入账
- 所有资金操作写入流水表，每一笔资金变动可审计追溯

### 模块 4：支付与充值模块

1. 用户发起充值请求，后端调用支付宝 SDK 生成沙箱支付链接
2. 用户跳转支付宝页面完成付款
3. 支付宝服务器异步 POST 通知后端 notify 地址
4. 后端做 RSA2 签名验签，校验订单、金额合法性
5. 校验通过，更新充值订单，增加用户余额
6. 返回`success`给支付宝，否则支付宝会重复推送回调通知

### 模块 5：反馈与消息通知模块

- 用户提交反馈，管理员后台查看、回复；反馈状态流转：待处理 →已回复 →已关闭
- 通知来源：交易事件自动通知、反馈回复通知、管理员全局广播通知
- 消息角标统计未读消息，点击查看后标记为已读

### 模块 6：AI 桌宠智能客服（项目创新点）

前端全局悬浮组件`AiPet.vue`，挂载在 App.vue，全站可见

- 桌宠可拖拽，拖拽位置持久化存入`user_pet`表，下次打开页面自动恢复位置
- WebP 动态待机动画，支持多皮肤切换，管理员后台上传皮肤素材
- 对话请求链路：用户输入消息 →请求后端`/pet/chat`接口 →`PetAiServiceImpl`
- 后端拼接业务限定提示词，调用通义千问大模型接口，返回对话内容渲染气泡
- 异常降级：大模型接口调用失败，自动切换关键词 Mock 回复兜底

**安全设计**

- 大模型 API 密钥只保存在后端配置文件，前端无法获取
- 系统提示词限制回答范围，只回答平台交易相关业务问题，减少无效 Token 消耗

## 六、后端包分层结构

```
com.trade.virtual_trade
├── VirtualTradeApplication.java     项目启动类
├── config/          5个配置类（跨域CORS、Redis、支付宝、定时任务、Web配置）
├── controller/      12个控制器，接收前端请求，参数校验
├── service/         14个业务接口 + impl/14个实现类，业务逻辑层
├── mapper/          11个MyBatis接口 + resources/mapper/*.xml SQL文件
├── entity/          11个实体类，映射数据库表
├── common/          Result统一返回结果封装
├── constant/        订单状态、业务常量
├── exception/       GlobalExceptionHandler全局异常处理器
├── task/            OrderTimeoutTask 订单超时定时任务
└── utils/           JwtUtil、密码工具、文件上传工具类
```

分层规范：Controller 只做参数接收、调用 Service；业务逻辑全部写在 Service；统一异常捕获，返回标准化 JSON 结果。

## 八、项目亮点

1. **资金托管模型**：冻结、解冻、资金划转三段式资金流转机制，事务保证资金操作原子性，配套资金流水表实现全程可追溯。
2. **订单超时自动处理**：Spring 定时任务扫描未支付订单，自动取消订单、资金回退、商品状态回滚。
3. **幂等性设计**：支付宝支付回调校验订单状态，防止重复回调造成重复入账。
4. **多层安全防护**：JWT 无状态认证、BCrypt 密码加密、Redis 接口限流、前端路由守卫，构建前后端分离安全体系。
5. **AI 客服安全中转**：大模型密钥后端托管，Prompt 业务范围限制，接口异常 Mock 降级兜底，兼顾功能与安全。
6. **特色交互设计**：全局可拖拽 AI 桌宠，支持 WebP 动画、皮肤切换、位置记忆，提升产品交互体验。
